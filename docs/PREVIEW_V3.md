## 2. Sidebar

- เดสก์ท็อป: ค่าเริ่มต้น **ย่ออัตโนมัติ** (แถบไอคอน 68px) ขยายเมื่อชี้เมาส์ / โฟกัสด้วยคีย์บอร์ด / กดปุ่มเมนู · ปุ่มหมุด = **เปิดค้าง**
- มือถือ (≤980px): Drawer เปิดด้วยปุ่มเมนู ปิดด้วยปุ่มปิด แตะพื้นหลัง หรือ Esc
- จำค่าในเครื่อง (`localStorage`): `hub.sb` (โหมด), `hub.hide` (หมวดที่ซ่อน), `hub.theme` (โหมดสี) — ไม่มีข้อมูลส่วนบุคคล
- ชื่อ “งานจราจรและความปลอดภัย” ตั้งค่าไม่ตัดบรรทัด และมีโค้ดย่อขนาดตัวอักษรอัตโนมัติถ้าฟอนต์ของเครื่องกว้างกว่าพื้นที่
- ตรามหาวิทยาลัย: `logoUrlTemplate + logoFileId` ใน `config.js` (ไฟล์แชร์แบบ “ผู้มีลิงก์ดูได้” อยู่แล้ว) ถ้าโหลดไม่ได้จะแสดงพื้นที่โลโก้แบบข้อความ

## 3. กราฟ

- วาดด้วย SVG ในหน้า ไม่ใช้ไลบรารีภายนอก วาดตามความกว้างจริงของกล่อง (ตัวอักษรไม่ย่อบนมือถือ)
- Tooltip เมื่อชี้/แตะ/โฟกัส: เดือน ชื่อชุดข้อมูล ค่าจริง และผลรวม · ปุ่มลูกศรเลื่อนระหว่างแท่ง
- คลิก (หรือ Enter) = เปิดหน้ารายละเอียดพร้อมกรองเดือนนั้น · จอสัมผัส: แตะครั้งแรกดูค่า แตะซ้ำเพื่อเปิด
- ไม่ซ้อนชุดข้อมูลต่างหน่วยในกราฟเดียว: คะแนน (1–5) แยกจากจำนวนผู้ตอบ, จำนวนรถ (คัน) แยกจากผู้ไม่สวมหมวก (ราย)

## 3.1 แผนที่จุดเกิดอุบัติเหตุ (`#accident-map`)

ลำดับการเลือกแผนที่ (ไม่มี API key ในไฟล์ใดของ Repository):
1. **Google Maps** — ใช้เฉพาะเมื่อผู้ดูแลใส่ Browser key ที่จำกัดสิทธิ์แล้วใน `config.js` (`googleMapsApiKey`) รอบนี้ตรวจแล้ว**ไม่มี key หรือสิทธิ์ Google Maps Platform ที่ใช้ได้** จึงไม่เปิดใช้ และไม่ได้สร้าง key ใหม่
2. **Leaflet + OpenStreetMap** (ค่าเริ่มต้น) — วิธีเดียวกับแผนที่ของ Dashboard AI เดิม (Main-AI-v1) ไม่ต้องใช้ key · ไลบรารี Leaflet 1.9.4 เก็บไว้ใน `assets/vendor/` (ไม่พึ่ง CDN) · ไทล์จาก `tile.openstreetmap.org`
3. **แผนผังตามพิกัดจริงในหน้า** — ใช้อัตโนมัติเมื่อไลบรารีหรือไทล์โหลดไม่สำเร็จ พร้อมข้อความแจ้งสถานะ ปุ่มลองใหม่ และปุ่มเปิด Google Maps / Dashboard AI เดิม

- จุดที่อยู่ใกล้กันรวมเป็นวงกลมตัวเลข กดเพื่อขยาย · ชี้/แตะจุดเห็นเฉพาะ **ประเภทเหตุ · ชื่อสถานที่ · เดือน**
- ไม่มีชื่อผู้แจ้ง เวลา รูปภาพ หรือข้อความเหตุการณ์ · ใช้เฉพาะพิกัดจริง 37 จุดจาก `data/stats.json` (`accidentMap`) — 1 จุดอยู่นอกกรอบวิทยาเขต (แจ้งให้ตรวจพิกัด)
- กรองตามประเภทและช่วงเดือนได้ · ตารางด้านข้างเลือกจุดแล้วแผนที่เลื่อนไปยังจุดนั้น

## 4. รายงานตรวจรับ รปภ. (`#report-guard`)

ตัวเลขทั้งหมดอยู่ใน `data/stats.json` (โมดูล `guardSatisfaction`, `guardFines`) ซึ่ง**ไม่ได้ถูกแก้ในรอบนี้** และตรวจซ้ำกับต้นทางเมื่อ 14 พ.ย. 2569 22:02 น. แล้วตรงกัน

| ชุดข้อมูล | เดือน | N | คะแนนรวม |
|---|---|---|---|
| รปภ.ส่วนกลาง (1 คำตอบ = ผู้ใช้บริการ 1 คน/ครั้ง) | ต.ค. 2569 | 9 คำตอบ | 4.38 |
| | พ.ย. 2569 (1–14 พ.ย.) | 54 คำตอบ | 4.72 |
| รปภ.ส่วนงาน (ส่วนงานกรอกค่าเฉลี่ย + จำนวนผู้ตอบ · ถ่วงน้ำหนักด้วยจำนวนผู้ตอบ) | ก.ย. 2569 | 125 คน / 2 รายการ | 4.61 |
| | ต.ค. 2569 | 660 คน / 9 รายการ | 4.62 |
| | พ.ย. 2569 | 2 คน / 2 รายการ | 4.95 |
| ค่าปรับ รปภ. (ประเภท “ปรับ รปภ.” ในแท็บ รายงานเหตุการณ์) | 1 ก.ค.–13 พ.ย. 2569 | 1 กรณี (ต.ค.) | 1,000 บาท* |

\* Sheet ไม่มีช่องยอดเงิน ใช้ 1,000 บาท/กรณีตามสูตรของแบบรายงานเดิม — **อัตรารอยืนยัน**

ด้านที่ประเมิน (ทั้งสองแบบ): การรักษาความปลอดภัย, การจัดการจราจร, การให้บริการ, การแต่งกาย, ความสุภาพ — สองแบบประเมินแสดงแยกกัน ไม่นำคะแนนมารวม

**ทำไมไม่ตรงกับหน้า “รายงานตรวจรับ รปภ.” ของระบบเดิม** — หน้าเดิม (`report_security_script.js` ใน `main`) อ่านจากแหล่งรุ่นเก่า:
- คะแนน: Google Form “แบบฟอร์มสอบถามข้อเสนอแนะการให้บริการรักษาความปลอดภัย (การตอบกลับ)” มี 9 ด้าน เฉลี่ยทุกคำตอบ ไม่แยกส่วนกลาง/ส่วนงาน
- ค่าปรับ: “Copy of รายงานเหตุการณ์ใหม่ล่าสุด (Responses)” (แถวล่าสุด 11 ต.ค. 2569) นับทุกแถวที่ช่องเหตุผลไม่ว่าง × 1,000 บาท

## 7. ผู้ช่วย AI

ผลตรวจระบบเดิม (Main-AI-v1 → DashboardAI, อ่านซอร์ส ไม่ได้ส่งคำถามทดสอบ):
- ส่ง `{action:'chat', userMessage, chatHistory}` ไปยัง Apps Script Web App ตัวเดียวกับที่ดึงข้อมูลแดชบอร์ด ไม่มีการยืนยันตัวตนผู้เรียก ไม่มีการจำกัดจำนวนคำถาม
- API key ของบริการ AI ไม่อยู่ในซอร์สฝั่งเว็บ (ถูกต้อง) แต่ Web App เดียวกันส่งคืนข้อมูลรายแถวได้ คำตอบจึงอาจมีรายละเอียดรายบุคคล

จึง**ยังไม่เชื่อมต่อ**ในหน้ารวม (`#ai` แสดงสถานะ “ยังไม่เชื่อมต่อ” + ปุ่มเปิด Dashboard AI เดิม) ข้อเสนอ: `proposals/ai-stats-worker.js` — Backend ที่ป้อน AI เฉพาะ `data/stats.json` เก็บ key เป็น Secret และอยู่หลัง Access

## 8. GitHub Pages เทียบกับ Cloudflare Pages

| ประเด็น | GitHub Pages (ที่ใช้อยู่) | Cloudflare Pages |
|---|---|---|
| จำกัดผู้เข้าชม | ทำไม่ได้ในแผนปัจจุบัน — การเผยแพร่แบบ Private ต้องใช้ GitHub Enterprise Cloud และ Repository แบบ private/internal ขององค์กร | ใส่ Cloudflare Access ด้านหน้าได้ (ยืนยันด้วยอีเมล OTP หรือ Google) แผน Zero Trust Free รองรับได้ถึง 50 ผู้ใช้ |
| ซอร์สโค้ด | แผน Free ต้องเป็น Repository สาธารณะ → ทุกไฟล์ใน Repo เปิดอ่านได้ | เชื่อม Repository แบบ private ได้ หรืออัปโหลดตรง |
| API / ค่าลับ | ไม่มีฝั่งเซิร์ฟเวอร์ ต้องพึ่ง Apps Script ภายนอก และห้ามมี key ในหน้าเว็บ | มี Pages Functions/Workers + Secrets — ทำ Stats API, Roster API, AI proxy โดยไม่เผย key |
| Preview ต่อ branch | ไม่มีในตัว (1 Repo = 1 เว็บไซต์) | ทุก branch ได้ URL ทดลอง (ควรใส่ Access ครอบ URL ทดลองด้วย เพราะ URL คงอยู่ถาวร) |
| ตารางเวรพร้อมรายชื่อ / ข้อมูลส่วนบุคคล | **ไม่เหมาะ** | ทำได้เมื่ออยู่หลัง Access และเก็บข้อมูลนอก Repository |
| ความคุ้นเคยของทีม | ระบบส่วนใหญ่อยู่ที่นี่แล้ว | มีระบบแบบสำรวจลานจอดเรือนไทยใช้งานอยู่แล้ว |

**แนวทางที่เสนอ**
1. หน้ารวมที่แสดงเฉพาะสถิติรวม (รุ่นนี้) → อยู่ GitHub Pages ต่อได้ ไม่ต้องจำกัดสิทธิ์
2. ส่วนที่มีรายชื่อหรือข้อมูลรายบุคคล (ตารางเวรพร้อมชื่อ, บุคลากร, AI ที่อ่านข้อมูลดิบ) → ทำเป็นโครงการ Cloudflare Pages แยก หลัง Cloudflare Access แล้วลิงก์จากหน้ารวม
3. ถ้าต้องการให้ทั้งหน้ารวมเห็นเฉพาะบุคลากร → ย้ายทั้งโครงการไป Cloudflare Pages + Access (ต้องมีผู้ดูแลบัญชี Cloudflare และกำหนดรายชื่อ/โดเมนอีเมลที่อนุญาต)
