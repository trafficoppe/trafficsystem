## 2. รายงาน รปภ. งานปริญญา (GPS) — สาเหตุ `#REF!` และวิธีแก้

- ลิงก์ที่ได้รับ `gid=1340605203` คือแท็บ **Guards** (รายชื่อ รปภ.) ไม่ใช่รายงาน — รายงานอยู่ที่แท็บ **Reports** (gid 1074767452)
- สูตรที่เคยเขียนไป `T_FINE!AG1` / `AM1` ล้มเหลวเพราะชีต `T_FINE` มี 31 คอลัมน์ (ถึง AE) — ไม่มีการเขียนข้อมูลเกิดขึ้น
- สูตรที่ย้ายไป `T_FINE!K41` ตอบ `#REF!` พร้อมข้อความจาก Google: **“Please use a desktop web browser to connect this sheet.”** = ยังไม่มีผู้กดอนุญาตให้ Sheet STAGING เชื่อม (IMPORTRANGE) กับ Sheet ปลายทาง ไม่ใช่ชื่อแท็บหรือช่วงผิด · ค่า `1` ของ `COUNTA(IMPORTRANGE(...))` คือการนับเซลล์ error ไม่ใช่จำนวนรายงาน — **ไม่ได้นำไปใช้**
- วิธีที่ใช้แทน: อ่านแท็บ Reports แบบ Read-only ผ่าน Connector เฉพาะคอลัมน์ K, L, P, W (ไม่อ่านชื่อ รปภ. รายละเอียด หรือรูป) แล้วนับในโปรเจกต์ (`tools/build_extra.py` มีตัวตรวจผลรวมต่อวัน)
- ผลตรวจ: 193 รายงาน (แถว 2–194) · Report_Date เป็นข้อความ `YYYY-MM-DD` · พิกัดเป็นตัวเลขครบ 193 · อยู่ในกรอบวิทยาเขต 184 · นอกกรอบ 9 (ไม่ได้ตัดออกจากการนับรายงาน เพราะหน้านี้ไม่แสดงแผนที่)
- Geo_Status รวม: WITHIN_RADIUS 65 · OUTSIDE_RADIUS 60 · POST_NO_COORDS 66 · LOW_ACCURACY 2 — POST_NO_COORDS สูงเพราะจุดปฏิบัติงานจำนวนหนึ่งในแท็บ Posts ยังไม่มีพิกัดอ้างอิง
- ยังไม่ได้นับ: Record_Status ทั้งคอลัมน์, แยกตามจุด/หน้าที่/ประเภทรายงาน, จำนวน รปภ. และจุด (แท็บ Guards/Posts) — ต้องอ่านเพิ่มหรือให้ STAGING เชื่อมได้
- ไม่มีพิกัดรายรายงาน ชื่อ หรือรูปในไฟล์ของ Repository · ไม่ใช้ข้อมูลนี้ในแผนที่อุบัติเหตุ

## 3. Sheet STAGING (ชีตคำนวณแยก ไม่ใช่ต้นทาง)

“STAGING – สถิติรวมสำหรับหน้ารวมงานจราจร (คำนวณจาก Sheet จริงแบบอ่านอย่างเดียว) – สร้าง 14.11.69” อยู่ใน Drive ของเจ้าของงาน สร้างขึ้นในโครงการนี้เพื่อคำนวณยอดรวมด้วย IMPORTRANGE/QUERY โดยไม่แตะ Sheet จริง
สูตรที่เพิ่มในแท็บ `T_FINE` เมื่อคืนวันที่ 14–15 พ.ย.: `K16:K20` (รถราง), `S1` (รถรางแยกส่วนงาน), `W1` (สถานะ Lost & Found), `W20:W21` (กิจกรรมพิเศษ), `K40:K41` (GPS — ยัง #REF!), `S40:S41` (เรือนไทย — ยัง #REF!), `K1` และ `K60` (Anywheel — ใช้ไม่ได้)
ตั้งแต่ได้รับคำสั่งรอบล่าสุด **ไม่มีการเขียนเพิ่ม** ใน STAGING · ถ้าต้องการให้ลบสูตรที่ไม่ใช้ แจ้งได้

## 4. ข้อจำกัดของข้อมูล

- **Anywheel:** ต้นทางเป็นรายวัน 576 แถวเริ่ม 1 ธ.ค. 2567 · คอลัมน์วันที่มีทั้งค่าวันที่และข้อความ (วัน/เดือนสลับ) คอลัมน์เดือนของ ม.ค.–ก.พ. 2569 รูปแบบปนกัน · ยืนยันยอดรายเดือนได้ มี.ค. 68,902 / เม.ย. 48,780 / พ.ค. 33,322 / มิ.ย. 24,510 ครั้ง · ระยะทางและเวลายังสรุปไม่ได้
- **รถเข้าออก:** มีเฉพาะรถเข้า · อัตราไม่สวมหมวก 70.5% สูงผิดสังเกต (บางวันจำนวนผู้ไม่สวมหมวกมากกว่ารถจักรยานยนต์) ควรตรวจการกรอก
- **Lost & Found:** ยอดในไฟล์สถิติหลัก (670) กับสถานะรายเดือน (671) ต่างกัน 1 รายการเพราะตรวจคนละเวลา
- **แบบสำรวจลานจอดเรือนไทย:** เปิดอ่านได้ (แท็บ RuenThai_Survey) แต่ยังไม่ได้สรุปสถิติ — STAGING ตอบ #REF! ข้อความเดียวกับ GPS และข้อมูลมีชื่อ/เบอร์/ทะเบียนรถ จึงไม่อ่านทั้งแท็บผ่าน Connector · ต้องให้เจ้าของเปิด STAGING เซลล์ `T_FINE!S40` บนคอมพิวเตอร์แล้วกด Allow access หนึ่งครั้ง
- **แบบทดสอบหมวกนิรภัย:** ไม่มี Sheet ปลายทาง จึงไม่มีสถิติ มีเฉพาะปุ่มเปิดแบบทดสอบ

## 5. แผนที่จุดเกิดเหตุ — สาเหตุ “Access blocked” และวิธีแก้

- สาเหตุ: ไทล์ `tile.openstreetmap.org` ปฏิเสธคำขอที่ไม่มี Referer ของเว็บไซต์ (เปิดไฟล์จากเครื่อง `file://`) แล้วตอบเป็นภาพ “Access blocked” · Dashboard AI เดิมใช้ได้เพราะเปิดผ่าน https
- ไม่มี Google Maps API key ที่ใช้ได้ และไม่ได้สร้าง key ใหม่
- วิธีแก้: (1) เปิดจากไฟล์ → ไม่เรียกไทล์เลย ใช้แผนผังจากพิกัดจริง + ปุ่มเปิดจุดใน Google Maps (2) เปิดผ่าน https → ตรวจไทล์ตัวอย่างก่อน ถ้าไม่ได้ HTTP 200 ใช้แผนผังพร้อมข้อความแจ้ง ถ้าได้จึงใช้แผนที่พื้นหลัง
- ข้อจำกัด: แผนผังไม่มีภาพถนน/อาคาร · แผนที่พื้นหลังจะเห็นได้หลังเผยแพร่ผ่าน https เท่านั้น (ยังไม่ได้ทดสอบกับไทล์จริงภายในหน้ารวม)

## 6. Lost & Found — รายการและรูป

- ระบบต้นทาง (`trafficoppe/lostfound`, `assets/lf-data.js`) ดึงข้อมูลสาธารณะด้วย `GET <API>?action=getPublicData` ได้ `{success, records[], generatedAt}` · ฟิลด์ที่ใช้: `type, title, location, reportedAt, images[] (Drive file ID), status, actionText, name` · รูป = `https://drive.google.com/thumbnail?id=<ID>&sz=w400` (รูปแบบเดียวกับต้นทาง)
- หน้ารวมดึงรายการ **เฉพาะเมื่อ** `config.js` ตั้ง `internalMode: true` และ `lostfoundApiUrl` — ค่าเริ่มต้นใน Repository คือปิด จึงไม่มีการเรียก API หรือรูปใด ๆ และไม่มีข้อมูลรายการในไฟล์ของ Repository
- เปิดโหมดนี้ได้เมื่อเว็บไซต์อยู่หลังการยืนยันตัวตนแล้วเท่านั้น (ข้อ 7) · ทดสอบแล้วด้วยข้อมูลสมมติ (กรอง ค้นหา แบ่งหน้า ขยายภาพ ภาพเสีย) — **ยังไม่ได้ทดสอบกับ API และรูปจริง**

## 7. การจำกัดสิทธิ์ก่อนใช้ข้อมูลจริง

- GitHub Pages ของ Repository สาธารณะจำกัดผู้เข้าชมไม่ได้ → ใช้ได้เฉพาะรุ่นสถิติรวม
- แนวทาง: Cloudflare Pages (โครงการใหม่แยกจากเว็บไซต์เดิม) + Cloudflare Access จำกัดอีเมล/โดเมนที่อนุญาต แล้วจึงตั้ง `internalMode: true`
- ยังไม่ได้ตรวจว่าบัญชี Cloudflare ที่เชื่อมอยู่สร้างโครงการ Pages และ Access ได้หรือไม่ — จะตรวจเมื่อได้รับ “อนุมัติให้ Deploy” · รหัสพนักงานไม่ใช่ระบบยืนยันตัวตนของเว็บไซต์

## 8. หน้าที่ยังเป็นทางเข้าระบบเดิม

บุคลากร (3 แถบ), ตรวจพื้นที่, ให้ความช่วยเหลือ, งานจราจร, ยานพาหนะทั้งหมด, ข้อมูลการจอดรถ, แบบฟอร์มบันทึกศูนย์วิทยุ, รายงานประจำวัน/วิทยุ/ประจำเดือน, ประวัติการตรวจสภาพ — ข้อมูลเป็นรายบุคคล/ภาพถ่าย ต้องแสดงหลังยืนยันตัวตน ยังไม่ได้ทำหน้าแสดงผลในระบบใหม่

## 9. ผู้ช่วย AI

Endpoint เดิม (Apps Script ของ Dashboard AI) รับคำถามโดยไม่ยืนยันตัวตนและตอบจากข้อมูลรายแถว จึงยังไม่เชื่อมต่อ — หน้า “ผู้ช่วย AI” แสดง “ยังเชื่อมต่อผู้ช่วย AI ไม่ได้” · ต้องมี Backend ที่ป้อนเฉพาะสถิติรวม เก็บ key ฝั่งเซิร์ฟเวอร์ และอยู่หลัง Access (ตัวอย่าง `proposals/ai-stats-worker.js`)
