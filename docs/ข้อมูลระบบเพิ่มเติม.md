## 3. Sheet STAGING (ชีตคำนวณแยก ไม่ใช่ต้นทาง)

“STAGING – สถิติรวมสำหรับหน้ารวมงานจราจร (คำนวณจาก Sheet จริงแบบอ่านอย่างเดียว) – สร้าง 14.11.69” อยู่ใน Drive ของเจ้าของงาน สร้างขึ้นในโครงการนี้เพื่อคำนวณยอดรวมด้วย IMPORTRANGE/QUERY โดยไม่แตะ Sheet จริง

- **Lost & Found:** รอบ 7 อ่านต้นทางซ้ำ (15 พ.ย. 18:12–18:37): ยอดแยกประเภทปรับเป็น 671 (พ.ย. แจ้งของหาย 27) ตรงกับยอดแยกสถานะแล้ว — รายการที่เพิ่มคือรายการที่บันทึก 14 พ.ย. 20:34 น. (สถานะ รอดำเนินการ)

## 5. แผนที่จุดเกิดเหตุ

- แหล่งแผนที่: ไทล์มาตรฐานของ OpenStreetMap ผ่าน Leaflet 1.9.4 — แหล่งเดียวกับแผนที่ในหน้ารายงานประจำเดือนของระบบเดิม (branch `main`: `report_script.js` ใช้ `tile.openstreetmap.org`) ไม่ใช้ API key
- สาเหตุ “Access blocked”: นโยบายการใช้ไทล์ของ OpenStreetMap กำหนดให้คำขอจากเว็บต้องมี Referer · ไฟล์ที่เปิดจากเครื่อง (`file://`) เบราว์เซอร์ไม่ส่ง Referer จึงถูกปฏิเสธ (ผู้ดูแล OSM ยืนยันว่ายังไม่มีวิธีที่ถูกเงื่อนไขสำหรับไฟล์ในเครื่อง) — หน้ารวมจึงไม่เรียกไทล์เลยเมื่อเป็น `file://`
- การใช้งานตามเงื่อนไข: ส่ง Referer (`referrerPolicy: strict-origin-when-cross-origin`), แสดงเครดิต “© OpenStreetMap contributors” พร้อมลิงก์, ไม่ส่ง `Cache-Control: no-cache`, ไม่ดาวน์โหลดไทล์ล่วงหน้า, ตรวจไทล์ตัวอย่าง 1 ครั้งก่อนใช้ และหยุดเรียกทันทีถ้าถูกปฏิเสธ
- ทางเลือกที่ตรวจแล้วไม่ใช้: CARTO basemaps (ปัจจุบันต้องมี API key) · Google Maps JavaScript/Embed API (ต้องมี key ซึ่งไม่มีและไม่ได้สร้าง)
- ผลตรวจ: ดูข้อ 10 — เปิดผ่าน https เห็นถนน/อาคารจริง · เปิดจากไฟล์ยังเป็นแผนผังตามพิกัดพร้อมข้อความแจ้งเหตุผล

## 6. Lost & Found — รายการและรูป

- ระบบต้นทาง (`trafficoppe/lostfound`, `assets/lf-data.js`): `GET <API>?action=getPublicData` ตอบ `{success, version, generatedAt, cache, serverMs, timing, records[]}` · ฟิลด์ของแต่ละรายการ: `type, title, location, reportedAt, itemDate, itemTime, refCode, images[] (Drive file ID), status, actionText, source` — **ไม่มีชื่อหรือเบอร์โทรผู้แจ้ง** · รูป = `https://drive.google.com/thumbnail?id=<ID>&sz=w400` (ขยาย `w1600`)
- ช่องทางผู้ดูแล (`adminGetData`, POST) ต้องยืนยันสิทธิ์ฝั่งเซิร์ฟเวอร์ — หน้ารวมไม่เรียก และรอบนี้ไม่ได้ส่ง POST ใด ๆ
- `config.js` ใส่ URL ของ API สาธารณะนี้แล้ว (ค่าเดียวกับที่อยู่ใน Repository `lostfound` ซึ่งเป็นสาธารณะ) แต่ `internalMode` ยังเป็น `false` — หน้ารวมจึงยังไม่เรียก API และไม่แสดงรายการ/รูป จนกว่าผู้ดูแลจะเปิดโหมดนี้
- ผลตรวจกับระบบจริง: ดูข้อ 10

## 7. การจำกัดสิทธิ์ก่อนใช้ข้อมูลจริง

- GitHub Pages ของ Repository สาธารณะจำกัดผู้เข้าชมไม่ได้ → ใช้ได้เฉพาะรุ่นสถิติรวม
- รอบ 7 เขียนบริการข้อมูลภายในไว้ใน `server/` + `apps-script/HubData.gs` (ตรวจ JWT ของ Cloudflare Access: ลายเซ็น/iss/aud/exp + รายชื่อผู้มีสิทธิ์; ถ้ายังไม่ตั้งค่าจะปฏิเสธทุกคำขอ) — **ยังไม่ได้ Deploy** รายการสิ่งที่ต้องตั้งค่าอยู่ที่ `server/README.md`
- `internalMode`, sessionStorage หรือการซ่อนเมนู ไม่ใช่การควบคุมสิทธิ์ — หน้าบุคลากร/ภาพตรวจพื้นที่/วิทยุ อ่านผ่านบริการที่ตรวจตัวตนเท่านั้น (ถ้าไม่มีบริการ หน้าจะแจ้งว่าต้องเข้าสู่ระบบภายใน ไม่อ่านจากช่องทางสาธารณะ)
- รหัสพนักงานไม่ใช่ระบบยืนยันตัวตนของเว็บใหม่ และไม่อยู่ในโค้ด/URL

## 8. หน้าที่ย้ายมาแสดงในระบบใหม่

รอบ 7 ย้ายครบทุกเมนูแล้วในระดับหน้าเว็บ (ไม่มีกล่อง “ยังไม่ได้ย้ายมาแสดงในระบบใหม่”) — ตารางทุกหน้าพร้อมสถานะ “อ่านข้อมูลจริงได้หรือยัง / ภาพ / สิ่งที่ขาด” อยู่ที่ `docs/ส่งมอบรอบ7.md` ข้อ 2

## 9. ผู้ช่วย AI

Endpoint เดิม (Apps Script ของ Dashboard AI) รับคำถามโดยไม่ยืนยันตัวตนและตอบจากข้อมูลรายแถว จึงไม่เชื่อมต่อ · รอบ 7: ปุ่มผู้ช่วย AI มุมล่างขวา + หน้าต่างสนทนาทำงานแล้วในฝั่งหน้าเว็บ และมีโค้ดบริการ `server/functions/api/chat.js` (ตอบจากสถิติรวม ตรวจตัวเลขในคำตอบ จำกัดจำนวนคำถาม) — ทดสอบด้วยบริการ AI จำลองเท่านั้น **ยังไม่เคยเรียกบริการ AI จริง** หน้าเว็บจึงยังแสดง “ยังเชื่อมต่อผู้ช่วย AI ไม่ได้”

## 10. ผลตรวจรอบ 6 (15 พ.ย. 2569) — แยก ระบบจริง / MOCK / ยังไม่ได้ทดสอบ

**ระบบจริง (เบราว์เซอร์ที่ออกอินเทอร์เน็ตได้ — แท็บบนโดเมน `trafficoppe.github.io` โหลดไฟล์ `dist/preview.html` ของ commit นี้จาก raw.githubusercontent.com มาแสดงในแท็บ ไม่ได้ Deploy)**

- Google Sheets (Connector อ่านอย่างเดียว): ฐานข้อมูลงานจราจร, แบบสำรวจเรือนไทย, GPS งานปริญญา, กิจกรรมพิเศษ, การบริการรถรางพิเศษ — เปิดอ่านได้ทั้งหมด
