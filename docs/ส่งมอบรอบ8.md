## 1. สถาปัตยกรรมที่ Deploy

- **Cloudflare Pages แบบ `_worker.js`**: ทุกคำขอ (หน้าเว็บ, `/api/*`, ภาพ) เข้า `worker/src/index.js` ก่อนเสมอ → (1) ด่านเครือข่าย → (2) session → (3) สิทธิ์ผู้ดูแล · ไฟล์หน้าเว็บส่งเฉพาะ `index.html`, `config.js`, `assets/`, `data/*.json` (ไม่มีข้อมูลบุคคล) · ไฟล์อื่นตอบ 404
- **ไม่มีด่านเครือข่าย (ค่าเริ่มต้น)**: เข้าได้จากทุกเครือข่าย · ข้อมูลภายในทุกเส้นทางต้องมี session · ด่านเครือข่ายแบบเลือกเปิด (`NETWORK_GATE=on` + `ALLOWED_CIDRS`) ยังอยู่ในโค้ดแต่ปิดไว้ และค่า `ALLOWED_CIDRS` อย่างเดียวไม่ปิด Login
- **`/api/health`**: สาธารณะตอบเพียง `{ok, now}` · `?probe=1` (ตรวจทุกแหล่งข้อมูล) ต้องเป็นผู้ดูแลที่ Login แล้ว
- **Login**: ช่องรหัสพนักงานช่องเดียว (ข้อความ ตัวเลข รักษาเลขศูนย์นำหน้า) → บริการอ่านแท็บ “รายชื่อเจ้าหน้าที่” คอลัมน์ “รหัสพนักงาน” แล้วเทียบตรงตัว · อ่านต้นทางไม่ได้ = ไม่ให้เข้า · ผิด 8 ครั้ง/10 นาทีต่อ IP = ล็อกชั่วคราว · ผิดรวมทุก IP 200 ครั้ง/ชม. = ล็อกการ Login ทั้งระบบชั่วคราว (กันไล่เดารหัสจากหลาย IP) · IP อ่านจาก `CF-Connecting-IP` ที่ Cloudflare ใส่ (ไม่มี = คีย์ unknown) · ไม่มีรหัสใดอยู่ในโค้ด
- **session**: token สุ่ม 320 บิต เก็บเฉพาะ SHA-256 ใน D1 · cookie `__Host-hub_s` HttpOnly + Secure + SameSite=Lax อายุ 12 ชม. · Logout ลบแถวใน D1 · หน้าเว็บไม่ใช้ `internalMode`/localStorage/sessionStorage เป็นหลักฐาน
- **ชุดข้อมูลหลัง Login** (`/api/data?dataset=`): `staff` (ไม่มีรหัส/ลายเซ็น/เบอร์), `incidents` (ไม่มีผู้รายงาน/เบอร์/รหัสนักศึกษา), `lostfound` (LF_New), `areaPhotos`, `radio`, `events` (ไม่มีชื่อผู้รายงาน), `gps` (แท็บ Reports ไม่มีชื่อ/รหัส รปภ.)
- **ภาพ** `/api/img?id=`: รับเฉพาะรหัสไฟล์ Drive ที่ปรากฏในชุดข้อมูล ไม่รับ URL · รูปที่ต้นทางเป็น GitHub user-attachments โหลดตรงจากต้นทาง
- **สถิติสด** `/api/stats`: เหตุการณ์ (รายวัน/รายเดือน/ผู้บาดเจ็บ), Lost & Found (LF_New รายวัน + แท็บรายการ พ.ศ. 2569 แยกประเภท/สถานะ), รถเข้า+หมวก · แยก `checkedAt` (เวลาที่อ่าน) / `lastRecordedAt` (เวลาบันทึกล่าสุดในต้นทาง) / วันที่ของไฟล์สถิติ · ส่วนที่อ่านไม่ได้ไม่ส่ง 0 แต่ส่งรหัสสาเหตุ แล้วหน้าเว็บคงข้อมูลล่าสุดพร้อมแถบแจ้ง
- **รายชื่อเวร** `/api/roster`: อ่านได้ทุกคนที่ Login · แก้ได้เฉพาะ `ADMIN_CODES` (ตรวจทุกคำขอ) · ID คงที่ · รุ่นข้อมูลกันเขียนทับ (409) · ชื่อซ้ำต้องยืนยัน · ประวัติทุกครั้งใน `roster_log`
- **ผู้ช่วย AI** `/api/chat`: session เดียวกัน · ข้อเท็จจริงสร้างจากสถิติรวม (ใช้ตัวเลขสดเมื่ออ่านได้) · ไม่ส่งชื่อ/รูป/เบอร์/รายการรายชิ้น · ตรวจว่าตัวเลขในคำตอบมีอยู่ในข้อเท็จจริง · จำกัด 6 ครั้ง/นาที 40 ครั้ง/วันต่อคน

## 5. วิธีตรวจบนเว็บไซต์จริง (ผู้ใช้ทำ ~10 นาที · จากเครือข่ายใดก็ได้)

1. เปิด https://mu-traffic-hub.pages.dev → หน้า Login ต้องไม่มีคำเตือนเรื่องเครือข่าย → กรอกรหัสพนักงานของตนเอง → ต้องเข้าได้ทันที
2. เปิดเมนู: บุคลากร · จัดการเหตุการณ์และอุบัติเหตุ (บล็อกรายละเอียด + แผนที่ถนนจริง) · Lost & Found · ตรวจพื้นที่ · รายงานวิทยุ · กิจกรรมพิเศษ · GPS งานปริญญา · ตารางเวร · ปุ่ม “ถาม AI” → ไม่ควรมีหน้าใดถาม Login ซ้ำ ถ้ามีข้อผิดพลาดหน้าจะบอกรหัสสาเหตุ (ส่งข้อความนั้นกลับมา)
3. กดออกจากระบบ → กลับหน้า Login · กด “ย้อนกลับ” แล้วต้องไม่เห็นข้อมูลภายใน
4. ลองรหัสผิด → “รหัสพนักงานไม่ถูกต้องหรือไม่มีสิทธิ์เข้าใช้งาน”
