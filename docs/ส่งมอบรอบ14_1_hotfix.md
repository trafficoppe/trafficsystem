## 2) สาเหตุ

**ยืนยันแล้ว (มีหลักฐาน)**
1. **หัวเว็บย้อนไปวันที่ไฟล์สรุป 15 พ.ย.** — `liveReadText()` ดูเฉพาะ `readAt` ซึ่งถูกลบเมื่อรอบล่าสุดล้ม → `renderStamp()` ใช้ `generatedAt` ของไฟล์สรุป ทั้งที่การ์ดยังแสดงค่าที่อ่านสำเร็จ 18:38 · ป้ายในหน้าเหตุการณ์ก็บอกว่า “ไฟล์สรุป” ผิดเช่นกัน (ทวนได้ใน local-mock)
2. **คำเตือนในภาพเป็นสถานะค้างจากก่อนพักเครื่อง** — สถิติคำสั่ง D1 รายนาที (Cloudflare GraphQL): ไม่มีคำขอใด ๆ ระหว่าง 19:02–21:23 · 21:23 มีการ Login ใหม่ (session เดิมหมดอายุ) และอ่านสำเร็จทั้ง 6 ส่วนที่ 21:23:37–40 · ภาพถูกถ่าย 21:22:59 จึงเป็นผลของรอบก่อนพักเครื่อง (แท็บที่ถูกซ่อนจะเลื่อนการอัปเดตไว้)
3. **ความล้มเหลวรายแหล่งเกิดจริงที่ 18:39** — มีการอ่านตาราง `stats_lkg` (`SELECT at, frag … WHERE k = ? AND cfg = ?`) 3 ครั้งในนาทีนั้น ซึ่งเกิดเฉพาะเมื่อแหล่งอ่านล้ม · D1 ไม่มี query error ใน 8 ชม. · Pages Functions ไม่มี exception หลุด (status success/clientDisconnected เท่านั้น)

**ยังไม่ยืนยัน:** ชนิด exception จริงที่ 18:39 — รุ่นนั้นกลืนสาเหตุใน `catch` (ไม่มี log) จึงย้อนดูไม่ได้ · ข้อความ 4 ชื่อ `internal` ไม่ได้พิสูจน์ว่า Sheet 4 แหล่งเสีย (คำขอ `rest` ล้มครั้งเดียวก็ติด 3 ชื่อ)

**จุดในโค้ดที่ทำให้เกิด `internal` ได้ (ทวนได้ใน local-mock และแก้แล้ว):**
- ต้นทางส่งหัวมาแล้วแต่เนื้อหาขาด/หมดเวลาระหว่างอ่าน (`await r.text()` อยู่นอก try) → `internal`
- อ่านสำเร็จแล้วแต่ขั้นเก็บสำรอง (`lkgCfg`/`waitUntil`) ล้ม → ถูกตัดสินว่าแหล่งล้มทั้งที่มีเวลาอ่านสด
- ตรวจ session ใน D1 ล้ม → HTTP 500 `internal` ของทั้งคำขอ

## 3) สิ่งที่แก้

บริการ: เนื้อหาขาด/หมดเวลา → `source-timeout`/`source-unreachable` · งานเก็บสำรอง LKG/แคชแยกจากผลอ่าน (ล้มได้โดยไม่ทำให้แหล่งล้ม และมี log) · LKG ที่รูปแบบเสีย/หมดอายุไม่ใช้ · D1 ตรวจ session ล้ม → 503 `auth-unavailable` (ไม่ตอบข้อมูล) · log มีโครงสร้าง (route/part/stage/ref/ชนิด/ข้อความที่ตัด URL-รหัส-ตัวเลขยาวแล้ว) · รหัสอ้างอิง (cf-ray) ในคำตอบที่ผิดพลาด
หน้าเว็บ: หัวเว็บ/ป้ายแหล่ง “ใช้ข้อมูลที่อ่านสำเร็จล่าสุดเมื่อ … · รอบล่าสุดอัปเดตไม่สำเร็จ N รายการ” (ใช้ไฟล์สรุปเฉพาะเมื่อไม่เคยอ่านสำเร็จ) · คำเตือน “อัปเดตข้อมูลบางรายการไม่สำเร็จ ขณะนี้แสดงข้อมูลที่อ่านสำเร็จล่าสุด” + “ดูรายละเอียด” (ชื่อไทย/อ่านสำเร็จเมื่อ/พยายามล่าสุด/สาเหตุ/รหัสอ้างอิง) + ปุ่มลองใหม่กันกดซ้ำ (เว้น 15 วิ) · ลองใหม่อัตโนมัติ 60 และ 120 วิ แล้วกลับเป็นทุก 5 นาที · การ์ด “วันนี้” บอก “ยอด ณ … รอบล่าสุดอัปเดตไม่สำเร็จ” แทนการให้ 0 ดูเป็นยอดล่าสุด · ฟื้นแล้วคำเตือนหายเอง ไม่โหลดหน้าใหม่ เนื้อหาบนจอไม่กระโดด

Regression ที่ล้มกับโค้ดก่อนแก้: worker 4 ข้อ (เนื้อหาขาด→internal, waitUntil ล้ม→ติด error, LKG เสีย→ถูกใช้, D1 session→500) · browser 3 ข้อ (คำเตือนไทย/รายละเอียดรายแหล่ง, หัวเว็บย้อนไปไฟล์สรุป, inc+rest ล้ม)
ผลทดสอบหลังแก้: worker 185/0 · session browser 141/0 · preview 136/0 · server 64/0 · HubRelay 33/0
